# 14 — Customer Ledger

## Overview

Every customer has a ledger — a running record of debits (amounts owed) and credits (payments received). Entries come from two sources:

- **Auto-generated** — written automatically when a trek is marked `Completed`. One Credit entry per stop for the amount paid, and one Debit entry per stop for any outstanding balance. These are cleared and re-written on each completion sync, so they always reflect the final recorded delivery data.
- **Manual** — added by staff directly via `POST /api/v1/customers/{customerId}/ledger`. These are never auto-modified.

When a trek is `Cancelled`, all auto-generated entries tied to that trek are removed from the ledger.

> **Balance formula:** `currentBalance = totalDebits − totalCredits`. A positive balance means the customer owes money.

## Endpoints

| Method | Endpoint | Auth | Purpose |
|---|---|---|---|
| `GET` | `api/v1/customers/{customerId}/ledger` | Required | Get ledger with running totals |
| `POST` | `api/v1/customers/{customerId}/ledger` | Required | Manually add a debit or credit entry |

## GET /api/v1/customers/{customerId}/ledger

Returns paginated ledger entries for the customer along with aggregate totals.

### Query parameters

| Parameter | Type | Description |
|---|---|---|
| `entryType` | `string?` | Filter by `Debit` or `Credit` |
| `pageNumber` | `int?` | Defaults to `1` |
| `pageSize` | `int?` | Defaults to `20`, max `100` |

### Field notes

| Field | Notes |
|---|---|
| `currentBalance` | `totalDebits − totalCredits`. Positive = customer owes money. |
| `trekNumber` | Present only on auto-generated entries linked to a trek, `null` on manual entries. |
| `isAutoGenerated` | `true` = written by the system on trek completion. `false` = added manually by staff. |
| `recordedBy` | Full name of the staff member who created the entry (or the driver for auto entries). |

Entries are ordered newest first.

### Errors
- `404` — customer not found

## POST /api/v1/customers/{customerId}/ledger

Manually record a debit or credit against a customer. Use this for adjustments, opening balances, or payments not tied to a trek.

### Request body

```json
{
  "entryType": "Credit",
  "amount": 200.00,
  "description": "Cash payment collected at branch",
  "recordedAt": "2026-09-09T10:00:00Z"
}
```

| Field | Type | Required | Notes |
|---|---|---|---|
| `entryType` | `string` | Yes | `Debit` or `Credit` |
| `amount` | `number` | Yes | Must be greater than `0` |
| `description` | `string` | Yes | Max 500 characters |
| `recordedAt` | `datetime?` | No | Defaults to current UTC time if omitted |

### Response `201 Created`

```json
{
  "id": "...",
  "entryType": "Credit",
  "amount": 200.00,
  "description": "Cash payment collected at branch",
  "isAutoGenerated": false,
  "recordedAt": "2026-09-09T10:00:00Z",
  "recordedBy": "Ama Owusu"
}
```

### Errors
- `404` — customer not found
- `422` — validation failed (amount ≤ 0, missing description, invalid entryType)

## How auto-generation works

When a trek status is changed to `Completed` via `PATCH /api/v1/treks/{id}/status`:

1. All existing auto-generated ledger entries for that trek's stops are deleted.
2. For each stop, the system sums `amtPaid` and `balance` across all products.
3. If `amtPaid > 0` → a **Credit** entry is written: `"Payment received — Trek {trekNumber}"`.
4. If `balance > 0` → a **Debit** entry is written: `"Outstanding balance — Trek {trekNumber}"`.

This means completing a trek is idempotent — you can re-trigger it and the ledger entries will always match the final recorded delivery data.

When a trek is `Cancelled`, all auto-generated entries linked to that trek are permanently removed.

> Manual entries (`isAutoGenerated: false`) are never touched by the auto-sync — they persist regardless of trek status changes.
